# Architecture: AI / DeepSeek

## Provider boundary

Follow the provider-neutral pattern already used in the chess repertoire project.

Environment:

```text
AI_ENABLED=false
LLM_PROVIDER=openai-compatible
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=
LLM_API_KEY=
LLM_TIMEOUT_SECONDS=120
LLM_MAX_RETRIES=1
LLM_DEBUG_LOGGING=false
```

Application code should depend on an OpenAI-compatible JSON client abstraction rather than importing DeepSeek-specific assumptions throughout the codebase.

## Machine-consumed output

When AI output affects stored metadata or application behavior:

- request JSON;
- validate against a Pydantic schema;
- reject malformed output;
- bound retries;
- record model, prompt version and schema version;
- keep deterministic fallbacks where practical.

## First candidate use cases

1. source-item topic/entity tagging;
2. spoiler classification assistance;
3. league-buzz clustering;
4. spoiler-safe summaries built only from safe projections;
5. structured extraction from articles/transcripts;
6. natural-language interpretation of recommendation requests.

## Non-authority

AI output does not override:

- temporal provenance;
- watched-game state;
- spoiler policy;
- deterministic game score inputs;
- source retention/access policy.

## Privacy/logging

Do not log:

- API keys or Authorization headers;
- full captured articles/posts/transcripts;
- complete prompts containing source content;
- raw model output.

Operational logs may include use case, source/item IDs, duration, attempt, status category and token usage.
