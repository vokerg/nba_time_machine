# Dashboard fixture prototype (issue #8)

The frontend now renders a spoiler-safe **synthetic demo**, not a connected
historical NBA feed. Its data comes from
`src/fixtures/read-models.json`, generated by the backend's real spoiler-policy
and read-model serializer:

```bash
cd backend
PYTHONPATH=src python scripts/export_read_model_fixtures.py
```

The fixtures contain one sealed game, its separate optional watchability /
reason / full layers, and a timeline-filtered media item. The full fixture is
**not** read into the default card, pregame recommendation, or media sections.
Only the explicit two-click result reveal projects it into a game card.
The verdict and "why" buttons use their own sparse validated contracts.
No numeric postgame quality is displayed by default.

The demo cursor, game acknowledgements and multiple favorite-team preferences
are stored in browser localStorage for continuity during a reload. The cursor
refuses to restore a position before the initial fixture timestamp and the UI
has only forward controls. This is demo persistence, **not** the backend
`/timeline/{profile_id}` service or the PostgreSQL acknowledgement table.
Advancing the demo cursor does not infer that a game has ended; such decisions
require a trusted observed final boundary. Revealing a game never changes the
cursor or the general media feed.

## Running and tests

```bash
cd frontend
npm install
npm test
npm run dev
npm run build
```

`npm test` exercises the strict card/media/disclosure contracts, spoiler field
rejection, pregame-interest ordering and forward-only cursor helpers using
Node 22. CI runs it before the production build.

## Remaining for a real end-to-end product

- Add an authenticated/explicit-profile dashboard composition endpoint
  returning policy-projected game-list and media-feed payloads, not raw ORM or
  provider results. Wire the timeline read/advance and game disclosure
  endpoints already available in the backend.
- Replace fixtures/localStorage with that service, with deliberate server-side
  initialization, loading and retry/error behavior. No synthetic score or
  generic static article should be presented as live data.
- Add a postgame watchability/ranking service under #10. The current
  "pregame pick" is based only on the available pregame interest field and
  is **not** postgame watchability.
- Expand the sparse synthetic slate to a trusted historical multi-game day,
  with policy-aware as-of game listing, media and true favorite-team identity.

No numeric postgame scores, photos, metadata, highlight durations or
outcome-dependent ordering may be introduced in the default card/read path.
